# DevStation MVP 计划

MVP 目标是打通一条本地研发主链路：

```text
任务 → Git 项目 → Agent 会话 → 本地运行 → 会话恢复 → Diff 评审 → 人工提交
```

SSH、远程运行、worktree、外部任务平台、自动提交和可视化工作流不在 MVP 范围内。

## 当前进度

阶段 0～3.2 已完成：Electron/React 框架、任务/项目/会话持久化，以及可跨应用重启接回的 OpenCode 终端闭环。

### M3.1：会话绑定的单 Agent 运行闭环 — 已完成

- AI 工作区主区固定为 PowerShell，不再嵌套 Agent 卡片。
- DevStation Session 固定绑定一个 PTY；切换界面只脱离显示，不结束进程。
- PTY 由独立终端宿主持有，应用重启后可按稳定 ID 热接回并回放有限快照。
- 首个 Agent 接入 OpenCode：新会话执行 `opencode`，冷恢复执行 `opencode --session <id>`。
- OpenCode 在首次交互后产生 Session ID；DevStation 从其本地数据库只读识别并保存，不修改供应商数据库。
- 数据库升级到 Schema v3，保存 `agent_type` 与 `agent_session_id`。

验收证据：独立宿主、终端管理、OpenCode 定位器和 TerminalPane 均有定向测试；Electron E2E 已验证跨应用重启保持同一 PTY PID 与终端内容。

### M3.2：终端稳定性收口 — 已完成

- 区分运行中、主动结束、正常退出、异常退出和宿主断连，并提供重新连接入口。
- 宿主协议带版本握手和只读诊断；连接异常不会静默留下失效的 UI 所有权。
- 用户主动结束 PTY 后，空闲宿主自动退出；应用重启仍保留运行中的 PTY。
- Windows 打包产物已验证“启动—应用重启—同 PID 接回—主动结束—宿主退出”。

基础分屏和多终端不属于本次稳定性收口，MVP 主链路继续保持一个 Session 对应一个 Agent PTY。

## M4：状态与会话管理

- `[L5]` 接收并标准化 OpenCode Hook 事件。
- `[L3]` 展示运行中、等待用户、完成和失败状态。
- `[L2]` 提供会话搜索、最近访问和状态筛选。
- `[L4]` 处理 Hook 缺失、原生会话不存在和恢复失败。

完成标准：用户能找到目标会话、判断 Agent 状态，并在 PTY 已结束时恢复正确的 OpenCode 历史会话。

## M5：Git 与 Diff 评审

- `[L2]` 读取分支、工作区状态和变更文件。
- `[L3]` 展示文本 Diff。
- `[L3]` 保存本地行级评论；MVP 不发送回 Agent。
- `[L3]` 处理非 Git 项目、脏仓库、大文件和二进制文件。

完成标准：用户可发现 Agent 变更、查看 Diff 并保存评审意见。

## M6：链路联调与内部发布

- `[L4]` 串联任务、项目、会话、终端、Hook 和 Diff。
- `[L3]` 补齐错误提示、恢复提示和诊断导出。
- `[L4]` 验证 Electron 安全配置、Preload 白名单和 IPC 参数边界。
- `[L4]` 验证 Windows 安装、升级、卸载和签名。
- `[L3]` 执行完整链路与异常恢复测试。

## 顺序与裁剪

```text
M4 状态可见 → M5 变更可评审 → M6 内部发布
```

不得裁剪：项目目录启动 Agent、会话恢复、Hook 状态、Git 变更和文件 Diff。

进度不足时依次裁剪：工作流继续占位、分屏固定为两栏、行级评论只保留新增/删除、文件页只读、首版只支持 OpenCode。
