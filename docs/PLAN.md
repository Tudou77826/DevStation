# DevStation MVP 计划

MVP 目标是打通一条本地研发主链路：

```text
任务 → Git 项目 → 工作流 → Agent 会话 → 本地运行 → 会话恢复 → Diff 评审 → 人工提交
```

MVP 包含一个真实可运行的工作流适配器，首个目标为 AAW。DevStation 负责启动、观测、确认和恢复，具体步骤仍由 Agent 按 AAW 契约执行。

SSH、远程运行、worktree、外部任务平台、自动提交、工作流可视化编排器和多工作流市场不在 MVP 范围内。

## Coding Agent 适配设计

终端只负责 PTY；Agent 的探测、启动、恢复、原生会话识别和事件接入由适配层负责。新增 Agent 不应修改 Terminal Host、Session 状态模型或 Renderer 的供应商逻辑。

稳定边界如下：

- Adapter 只返回结构化 `executable / args / env`，Main 负责校验和启动；Renderer 不能提供任意命令、工作目录或环境变量。
- 一个 DevStation Session 固定一个 `agentId`；原生会话引用必须经过对应 Adapter 校验，恢复失败不能静默创建新会话。
- Agent 能力与设置由版本化 Descriptor 声明；Registry 拒绝声明与实现不一致的 Adapter，通用设置页不包含供应商分支。
- 供应商 Hook/Plugin 事件是 Agent 状态事实；PTY 生命周期只表示终端连接情况，不能推断 Agent 正在工作。
- 受管集成只能增量维护带 DevStation 标识的配置，必须可诊断、可重复执行、可卸载，且不能覆盖用户内容。

新增内置 Agent 按[适配器接入指南](./ADDING_CODING_AGENT.md)实施，并通过现有契约测试、确定性 E2E 和显式真实 CLI Smoke 验收。MVP 继续使用 Agent 原生 TUI，不接入程序化对话协议；声明式 CLI Profile 与外部可执行插件留待后续评估。

## M6：AAW 工作流最小适配

- `[L4]` 建立 `WorkflowAdapter` 边界，统一可用性探测、SR 工作流创建、状态读取和用户确认。
- `[L4]` 接入 AAW CLI：支持受控配置运行器和 `aaw.py` 路径，只执行固定命令，在项目目录运行并校验 JSON 输出。
- `[L3]` 将工作流实例关联到任务、项目和工作会话，保存供应商、原生 ID 与最后同步状态。
- `[L3]` 用真实步骤、等待确认和产物路径替换当前模拟数据；进入页面时同步，并提供手动刷新和受控的低频同步。
- `[L4]` 处理 CLI 缺失、版本不兼容、输出损坏、工作流不存在和恢复失败。

AAW 是工作流状态的唯一事实来源。`status` 可能触发 AAW 自动更新，`next` 会推进步骤状态；两者都不得被当作无副作用的高频轮询。

完成标准：用户可从任务启动 AAW SR 工作流；Agent 在关联项目和会话中执行；应用重启后仍能找到该工作流，并展示来自 AAW 的真实状态与产物。

## M7：链路联调与内部发布

- `[L4]` 串联任务、项目、工作流、会话、终端、Hook 和 Diff。
- `[L3]` 补齐错误提示、恢复提示和诊断导出。
- `[L4]` 验证 Electron 安全配置、Preload 白名单和 IPC 参数边界。
- `[L4]` 验证 Windows 安装、升级、卸载和签名。
- `[L3]` 执行完整链路与异常恢复测试。

## 顺序与裁剪

```text
M5 变更可评审 → M6 工作流可运行 → M7 内部发布
```

不得裁剪：项目目录启动 Agent、会话恢复、Hook 状态、Git 变更、文件 Diff 和一个真实工作流适配器。

进度不足时依次裁剪：第三批 Agent 后置；工作流只支持 AAW 且不提供编排编辑；分屏固定为两栏；行级评论只保留新增/删除；文件页只读。
