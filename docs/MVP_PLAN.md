# DevStation MVP 实施计划

## 1. 目标

DevStation MVP 用于验证一条本地 AI 辅助研发链路：

```text
手动创建任务
→ 关联本地 Git 项目
→ 创建 Agent 会话
→ 通过终端运行 CLI Agent
→ 通过 Hook 跟踪会话状态
→ 查看和评审代码 Diff
→ 人工完成提交
```

MVP 优先保证链路顺畅、状态清晰和会话可恢复，不追求完整 IDE 或企业研发平台能力。

## 2. 技术基线

- 桌面框架：Electron
- 前端：React + TypeScript
- 构建工具：Vite
- 本地终端：xterm.js + node-pty
- 本地存储：SQLite
- Git：调用本地 Git CLI
- UI 方向：Codex 的整体布局与交互方式，参考 Orca 的终端、Diff 和 Agent 状态体验

应用采用 Electron 的标准分层：

```text
Renderer
  React UI、任务、会话、Diff、终端视图

Preload
  向 Renderer 暴露经过约束的桌面 API

Main
  PTY、Agent 进程、Git、Hook、SQLite、文件系统
```

Renderer 不直接访问 Node.js，所有系统能力通过 Preload 白名单 API 调用。

## 3. MVP 范围

### 3.1 产品能力

- Codex 风格的桌面布局
- 手动创建和管理任务
- 添加和管理本地 Git 项目
- 任务关联项目和 Agent 会话
- 通过终端运行 CLI Agent
- Agent Hook 状态跟踪
- 会话保存、搜索和恢复
- Git 状态和当前分支展示
- 文件 Diff 和本地行级评论
- Windows 安装包

### 3.2 Orca 继承范围

- 整体视觉风格与部分通用 UI 组件
- PTY 与终端运行机制
- 终端分屏、滚动记录和恢复机制
- Agent Hook 与会话状态处理思路
- Git 状态读取和 Diff 展示组件

继承 Orca 源码时保留其 MIT License 和版权声明。优先抽取独立模块，不直接在 Orca 仓库中删改形成产品。

### 3.3 非目标

- 内网任务平台对接
- SSH 和远程运行
- OpsCopilot 集成
- Git worktree
- 多 Agent 并行编排
- 完整代码编辑器
- 自动提交和创建 PR
- Diff 评论自动发送给 Agent
- 可视化工作流编辑器
- 移动端、模拟器、语音和 Computer Use

## 4. UI 信息架构

左侧边栏包含三个一级入口：

- 任务面板
- AI 空间
- 工作流

二级目录跟随一级入口切换：

- 任务面板：任务状态和任务列表
- AI 空间：项目和工作会话
- 工作流：MVP 仅提供占位入口或固定流程说明

用户入口固定在左侧底部，点击后向上展开个人信息、Agent 设置、应用设置和退出登录。

AI 空间的主工作区域包含：

- 对话
- 变更
- 终端
- 文件

输入框固定在中间区域底部。右侧面板按需展示任务摘要、Agent 状态和代码变更，可收起。

## 5. 实施阶段

以下周期按 2～3 名研发并行协作估算，总周期约 7～8 周。

### LLM-Agent 难度评级

难度表示 LLM-Agent 在具备完整仓库上下文、可运行测试和可访问 Orca 参考代码的前提下，独立完成任务并一次验收通过的难度。

| 等级 | 含义 | 推荐协作方式 |
|---|---|---|
| L1 低 | 改动局部、规则明确、容易自动验证 | Agent 可独立完成，人工快速检查 |
| L2 较低 | 常规功能实现，涉及少量模块 | Agent 主导，人工验收 |
| L3 中 | 跨模块设计或存在多个边界条件 | Agent 实现，关键节点人工评审 |
| L4 高 | 涉及进程、状态恢复、安全或平台差异 | 人工定方案，Agent 分步实现 |
| L5 很高 | 需要理解和拆解大型外部系统，未知风险高 | 先做技术 Spike，人工主导决策 |

阶段综合难度：

| 阶段 | 难度 | 主要原因 |
|---|---|---|
| 阶段 0 | L5 | Orca 终端抽取是首要技术不确定性 |
| 阶段 1 | L2 | UI 结构明确且易于视觉验收 |
| 阶段 2 | L3 | 数据模型和持久化边界需要提前稳定 |
| 阶段 3 | L5 | PTY、流控制、进程生命周期和恢复复杂 |
| 阶段 4 | L4 | 不同 Agent 的 Hook 与恢复协议存在差异 |
| 阶段 5 | L3 | Git 边界情况较多，Diff UI 相对成熟 |
| 阶段 6 | L4 | 跨模块联调、安全和安装环境验证复杂 |

### 阶段 0：技术验证与工程初始化

周期：3～5 个工作日

工作内容：

- `[L2]` 初始化 Electron、React、TypeScript 和 Vite 工程
- `[L3]` 建立 Main、Preload、Renderer 和 Shared 目录边界
- `[L5]` 从 Orca 抽取最小终端验证代码
- `[L3]` 使用 node-pty 启动一个本地 Shell
- `[L3]` 在指定目录启动一个 CLI Agent
- `[L1]` 明确 Orca 代码来源和许可证保留方式
- `[L2]` 建立基础测试、Lint 和打包流程

验收标准：

- DevStation 可以启动
- 可以打开终端并正常输入、输出和调整尺寸
- 可以从终端启动至少一个目标 Agent
- Windows 开发环境可以稳定构建

如果终端抽取不可行，应在本阶段调整复用策略，不进入大规模 UI 开发。

### 阶段 1：UI 框架

周期：1 周

工作内容：

- `[L3]` 实现 Codex 风格应用框架
- `[L2]` 实现一级菜单和动态二级目录
- `[L1]` 实现左下角用户入口及扇出菜单
- `[L2]` 实现中间主工作区和可收起右侧面板
- `[L2]` 实现对话、变更、终端、文件页签
- `[L2]` 实现暗色主题、空状态和加载状态
- `[L2]` 支持侧边栏收起和面板宽度调整

验收标准：

- 三个一级入口切换正确
- 二级目录随一级入口变化
- 用户菜单位置和交互符合设计
- 主工作区在常用窗口尺寸下无布局溢出

本阶段使用模拟数据，不依赖后端功能完成。

### 阶段 2：任务、项目与本地存储

周期：1 周

工作内容：

- `[L3]` 设计 Task、Project、Session 的最小数据模型
- `[L3]` 接入 SQLite
- `[L2]` 实现任务创建、编辑、完成和搜索
- `[L2]` 实现本地项目添加、移除和 Git 仓库校验
- `[L2]` 实现任务与项目关联
- `[L2]` 实现项目下的工作会话列表
- `[L1]` 实现置顶、最近访问和基础排序

验收标准：

- 用户可以手动创建任务
- 用户可以添加本地 Git 项目
- 用户可以从任务创建工作会话
- 应用重启后数据完整保留

### 阶段 3：终端与 Agent 运行

周期：1～2 周

工作内容：

- `[L4]` 接入 xterm.js 和 node-pty
- `[L4]` 实现终端创建、输入、输出、resize 和关闭
- `[L4]` 实现基础分屏
- `[L4]` 保存终端元数据和有限滚动记录
- `[L4]` 处理 Agent 正常退出和异常退出
- `[L4]` 建立最小 Agent 适配接口
- `[L4]` 首版接入 1～2 个 CLI Agent

Agent 适配接口至少包含：

- Agent 类型和显示名称
- 启动命令与参数
- 工作目录
- 环境变量
- Hook 安装方式
- Session ID 获取方式
- 原生恢复命令

验收标准：

- 可以在任务关联的项目目录启动 Agent
- 多个终端可以独立运行
- 关闭并重新打开工作区后可以恢复终端显示状态
- Agent 退出后 UI 状态正确更新

MVP 的恢复目标是恢复会话入口和必要终端记录，不承诺恢复已退出的操作系统进程。

### 阶段 4：Hook 与会话管理

周期：1 周

工作内容：

- `[L5]` 接收和标准化 Agent Hook 事件
- `[L4]` 记录 Agent Session ID
- `[L2]` 将 Agent 会话关联到 Task 和 Project
- `[L3]` 定义运行中、等待用户、完成、失败等状态
- `[L2]` 在侧边栏展示会话状态
- `[L2]` 实现会话搜索和最近访问
- `[L4]` 通过 Agent 原生命令恢复历史会话

验收标准：

- Agent 状态变化能够及时显示
- 应用可以找到任务对应的 Agent Session
- 用户可以从历史工作会话恢复 Agent 对话
- Hook 缺失或异常时不会破坏终端基本使用

MVP 不解析和重建所有 Agent 的完整对话历史。

### 阶段 5：Git 与 Diff 评审

周期：1～2 周

工作内容：

- `[L2]` 获取当前分支和工作区状态
- `[L2]` 展示新增、修改、删除和未跟踪文件
- `[L1]` 展示文件变更数量
- `[L3]` 接入文件 Diff Viewer
- `[L2]` 实现变更文件列表
- `[L3]` 实现本地行级评论
- `[L2]` 将 Git 和 Diff 状态展示在右侧面板及底部状态栏
- `[L3]` 对非 Git 项目、脏仓库和大文件提供明确提示

验收标准：

- Agent 修改文件后，界面能够自动发现变更
- 用户可以查看文本文件 Diff
- 用户可以添加、修改和删除本地行级评论
- 应用重启后评论仍然存在

### 阶段 6：链路联调与发布

周期：1 周

工作内容：

- `[L4]` 串联任务、项目、会话、终端、Hook 和 Diff
- `[L3]` 完善错误、空状态和恢复提示
- `[L2]` 增加异常日志和诊断信息导出
- `[L4]` 校验 Electron 安全配置和 IPC 参数
- `[L3]` 完成 Windows 安装包、卸载和升级验证
- `[L1]` 完成 Orca 许可证声明
- `[L3]` 执行核心链路回归测试

验收标准：

- 用户可以完整完成 MVP 目标链路
- 应用异常退出后任务和会话数据不丢失
- Agent 或 Git 命令失败时提供可执行的错误提示
- 新机器可以通过安装包完成安装并正常运行

## 7. 优先级与裁剪原则

优先级从高到低：

1. 终端和 Agent 能稳定运行
2. 任务、项目和会话关联准确
3. Hook 状态可靠且会话可恢复
4. Git 变更能够及时展示
5. Diff 评审体验清晰
6. 视觉细节和辅助操作

出现进度风险时，按以下顺序裁剪：

1. 工作流入口只保留占位
2. 终端分屏缩减为固定两栏
3. 行级评论缩减为只新增和删除
4. 文件页签只提供只读预览
5. 首版只支持一个 CLI Agent

不得裁剪的能力：

- 手动任务创建
- 项目关联
- 单终端运行 Agent
- Hook 状态跟踪
- 会话恢复入口
- Git 变更和文件 Diff

## 8. 主要风险

### Orca 模块耦合

终端或 Diff 组件可能依赖 Orca 的 Store、IPC 和运行时。阶段 0 必须先验证最小抽取路径，禁止直接复制整个应用框架。

### Windows PTY 稳定性

重点验证中文输入、PowerShell、窗口 resize、大量输出、Agent 退出和应用异常关闭。

### Agent Hook 差异

不同 Agent 的 Hook 和恢复协议不同。通过适配接口隔离差异，首版不追求统一完整对话格式。

### 会话恢复边界

DevStation 负责保存会话关联信息，并调用 Agent 原生恢复能力；不自行模拟或重建 Agent 内部状态。

### Electron 权限边界

Renderer 保持沙箱和上下文隔离，禁止直接启用 Node.js。命令、路径和 IPC 参数必须在 Main Process 校验。

## 9. MVP 完成定义

满足以下条件时，MVP 可以进入内部试用：

- 用户可以创建任务并关联本地 Git 项目
- 用户可以从任务创建工作会话
- 用户可以在工作会话中启动并使用 CLI Agent
- 用户可以看到 Agent 当前状态
- 用户可以在应用重启后找到并恢复会话
- 用户可以查看 Agent 产生的文件变更和 Diff
- 用户可以保存本地行级评审评论
- 完整流程无需 SSH、worktree 或外部任务平台
- Windows 安装包通过基础安装、升级和卸载验证
